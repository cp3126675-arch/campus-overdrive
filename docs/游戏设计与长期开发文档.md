## 1. 产品定义与体验目标

### 1.1 一句话定义

一款非官方清北校园题材的 **2D 徽章合成动作竞速游戏**：玩家操控中央徽章，在移动的校园实景战场上躲弹、打课本、抢鹅腿，将院徽合成清华校徽，最终击破二校门 Boss，挑战更短通关时间。

### 1.2 玩家与使用场景

面向熟悉校园生活、清北梗或喜欢短局动作游戏的玩家。陌生玩家也应能靠预警、轮廓和操作反馈理解规则；知道梗的玩家则能从造型和招式认出出处。

现阶段以浏览器即开即玩为入口，桌面键盘与手机横屏同时支持。单局可重开，无账号前置要求。实际局长取决于主修、随机进程与操作，目前没有固定时限；“短局”的合理时间区间需要真人试玩后确定。

### 1.3 四条设计原则

1. **笑点进入操作。** 鹅腿是要追的补给，鸭腿是要躲的代价；号码票封路、车轮迎面滚来，梗不只是一段说明文字。
2. **升级立刻有反馈。** 合成改变中央徽章、武器规模与伤害，并提供冲击波、短暂保护和音画反馈。
3. **热闹但能看清。** 徽章、敌弹、危险区、补给优先于背景与装饰；威胁越大，预警越清楚。
4. **再来一局有目标。** 通关之后比较完整通关时间，失败后知道自己死在哪里，以及下次能如何改变操作。

### 1.4 已确定、不应回退的方向

|编号|产品决定|

## 3. 玩家流程与核心循环

### 3.1 完整流程

**主菜单 → 搜索并选择主修 → 看普攻 / Q 技能说明 → 开始 → 移动与自动攻击 → 拾取 / 合成 → 进度 Boss → 下一检查点 → 合成清华 → 清完前置 Boss → 二校门最终战 → 收尾动画 → 结算 / 再挑战。**

开局前设置与战斗分离。局内不切换主修，重新选择需要回到菜单。重新挑战会新建一局，随机合成链与前六 Boss 顺序可能改变。

### 3.2 每个时间尺度的操作目标

|尺度|玩家在做什么|期望反馈|
|---|---|---|
|瞬间|走位避弹、接鹅腿、避鸭腿|位置可控、命中明确、红绿补给可区分|
|几秒|用车神冲刺穿过危险，找机会开 Q|开技能能改变当前处境|
|十几秒|收集一对徽章、合成升级|火力增强、冲击波解围、进度推进|
|一关|识别 Boss 招式，利用空道输出|记得住的攻击规律，而不是只拼血量|
|一局|活到合成清华并击破最终 Boss|胜负、合成时间、通关时间自然结算|
|多局|换主修、理解套路、缩短用时|后续需要历史成绩与公平比较支持|

### 3.3 状态与时间

当前模式为菜单、进行中、暂停、胜利、失败。手机物理竖屏时使用旋转的横屏舞台，不再因此阻止模拟与战斗输入。切离窗口会暂停，重新进入由现有暂停逻辑继续处理。

- 通关计时包含打击停顿，排除暂停与结束收尾。
- 合成清华时记录 `forgedAt`；完整胜利时间晚于或等于该时刻。
- 胜负一旦确定，成绩冻结；约 2.6 秒收尾后显示结算。
- 没有 300 秒强制失败，没有 12 学分通关门槛。
- 当前计时按实际帧间隔累加，但物理更新每次最多推进 0.05 秒。低帧率下，两者可能产生差异；公平竞速上线前需要专门处理，见 P0-03。

## 4. 徽章、合成与成长

### 4.1 合成链和库存

- 每局合成链 15 级：所选方向映射的起始徽章 → 随机 13 枚其他院徽 → 清华校徽。
- 第 15 级对应代码等级索引 14。本文提到“最高索引”时使用 0–14；玩家看到的等级为 1–15。
- 中间顺序是游戏随机成长路线，不代表院系排名。
- 初始库存为两枚 1 级徽章；库存最多 5 枚，最大徽章居中，其余环绕。
- E 优先合成可用的最高同级对，两枚变成一枚高一级徽章。
- 地面徽章不会自行合成。
- 满包时，碰到同级地面徽章可直接合成；若库存没有可合成对，允许更高阶掉落替换最低徽章，低阶徽章留地。其余情况弹开掉落，避免无限塞入。

### 4.2 合成反馈

合成增加进度、技能充能、短暂保护和少量生命，并产生近身伤害、击退、环形冲击和声音。合成最终校徽另提供一次回血和保护，并清除剩余徽章掉落。

中央火力交替使用当前徽章武器与所选院系弹道；僚机保持各自徽章的武器。伤害依徽章等级增长，不应让低级僚机与高级中央徽章完全等价。

### 4.3 地面掉落控制

|项目|v0.4.1 数值 / 行为|
|---|---|
|地面徽章上限|10 枚|
|徽章存活|22 秒，临近过期淡出|
|普通小怪掉落概率|22%|
|加急怪掉落概率|40%|
|掉落公共冷却|0.75 秒|
|稀疏补给|约每 10 秒检查，地面不足 3 枚时补一枚|
|保底奖励与上限冲突|有指定等级的奖励替换最旧地面徽章|
|常规掉落等级|接近当前最高等级的下一阶，少量再低一阶，最高普通掉落为索引 12|
|合成清华之后|不再生成徽章掉落，专注剩余 Boss|

这是加速成长的合成玩法，不是必须拾取 2 的 14 次方枚初始徽章的纯二进制合成。Boss 与任务奖励共同保证推进。

## 5. 主修与技能系统

### 5.1 方向目录的口径

使用 2026-09-07 的[清华官网院系设置](https://www.tsinghua.edu.cn/yxsz.htm)目录快照，去重后 126 个可选方向，包含学院、院内系、书院及同页研究教学机构。它不是“清华有 126 个学院”，也不是官方招生专业目录。

全方向表见本文附录 A；原始目录在 `docs/research/tsinghua-units-2026-09-07.json`，运行数据在 `lib/departments.json`。新增或改名必须对照目录来源；找不到对应徽章时使用既有映射，不伪造官方标识。

### 5.2 设计方法

每个方向的设计应能连成一句话：**专业习惯 / 广为人知的昵称 → 可识别的物件或符号 → 战斗行为 → 夸张结果**。

例如建院赶图变成反弹蓝图盾；法学“法庭肃静”变成冻结领域；天文“坍缩”变成引力聚怪；视传“Logo 再大一点”变成放大的光束。

“贵系、无系、雷系、茶园、仙院”等有已记录的校园称呼来源；其他不少招式是学科特点的原创夸张。不能把原创段子统一宣传为“全网公认刻板印象”。

### 5.3 当前 14 类 Q 技能

|机制|实际作用|辨识与平衡重点|
|---|---|---|
|蓝图盾 guard|反射附近敌弹，减伤 45%，伤害近敌|反弹前后阵营清楚；不能无条件覆盖整场|
|旋刃 blades|多条近身旋转长刃|刃面与命中范围一致|
|冲击环 wave|连续扩散的环面伤害|圆心不是整圆伤害，允许贴近或穿环|
|治疗场 heal|缓慢回血并伤害近敌|治疗量与输出互相制约|
|冻结 frost|区域伤害与明显减速|Boss 部分减速，不永久定身|
|无人机 drones|环绕单位发射追踪弹|与徽章僚机区分，限制弹量|
|引力 gravity|拉近敌人，中心伤害更高|聚怪有风险，中心效果可辨|
|光束 beam|两条旋转贯穿光束|视觉长度与判定统一|
|火焰 flame|朝移动方向的扇形持续火焰|方向可理解，扇面外不误伤|
|冲锋 rush|提高移动速度并碾压近敌|与公共车神技能不混淆|
|雷暴 storm|锁定附近多个敌人连续打击|显示实际锁定对象|
|轰炸 rain|在目标处进行范围打击|爆点可见，伤害覆盖有限|
|斩杀 execute|低血量目标额外伤害|强度依目标剩余生命变化|
|轨道 orbit|多枚卫星绕身碰撞|能看出卫星实际接触位置|

初始充能 60，满 100 才能发动；击杀 +4、合成 +16、吃鹅腿 +8。技能活动期间不累积新充能。单次持续时间依方向配置，不能把同一机制换名当成完全不同的独立玩法。

### 5.4 公共车神技能

所有方向保留学堂路车神：空格 / 触摸按钮发动，4 秒冷却，约 0.72 秒冲刺，可以转向，提供短暂保护和一次性目标碰撞伤害。

真实照片在玩家徽章处叠加，最高不透明度 88%，约 0.08 秒淡入、末尾 0.16 秒淡出；中央徽章始终绘制在照片上方。此处以当前代码为准，历史文档中的 46% 已过时。

### 5.5 后续院系差异化重点

先选出不同机制的代表主修做深度调整，验证射程、爆发、控制、防御与操作难度，再把结果扩展到同机制方向。优先解决名字与作用不匹配、选项过多难选、少数配置明显碾压其他方向等问题。126 个方向的覆盖完成不代表 126 个方向已平衡完成。

## 6. 教材怪、作业、考试与绩点

### 6.1 教材小怪

原数学、计算机、建筑方向保留 24 本真实封面，新增 168 张清华出版社实际出版物封面，共 192 张。126 个方向显式映射学科书库，选中主修后只加载该组 2–8 张封面；相近方向可共用相关课程书库。四年级战斗强度仍使用原 24 种基础数值模板，书名不再被虚构“讲义怪”覆盖。扩展方向按阶段主教材与相关教材轮换，图书来源、学科匹配和游戏年级是不同概念，不冒充清华官方课表。正文画面优先保留真实封面，触屏仅在小怪接近、受击或加急时显示完整标题，以降低文字遮挡。

新生成怪物使用当前年级资料；已在场低年级怪不会瞬间替换。年级同时受时间与合成进度推动，上限大四：

`年级 = min(4, 1 + max(floor(活动时间/55), floor(最高索引/4)))`

不同教材的生命、伤害、速度、大小不同。加急怪更耐打、接触伤害更高。大三资料会远程发题，大四资料一次发三枚；并非所有敌人只靠贴身碰撞攻击。

### 6.2 DDL 作业

35 秒为一个提交窗口，以下 6 项循环。完成后本窗口显示已提交，到下一个窗口换题。

|作业|目标|
|---|---|
|高数作业|击败 10 只作业怪|
|院徽实验|完成 2 次合成|
|小组作业（只有你在做）|击败 18 只作业怪|
|资料收集报告|拾取 8 枚院徽|
|合成进阶作业|完成 3 次合成|
|期末复习清单|击败 22 只作业怪|

完成获得 2 学分、恢复 12 生命和一枚奖励徽章。逾期记一次失败，生成两只追债加急怪，每只被击败可补修 1 学分。普通随机加急怪不自动给补修学分。

非 Boss 阶段持续到一定时长会出现 DDL 扫描墙：当前为本轮 25 秒后启动，先 2 秒预警再扫过；碰墙扣血，可用冲刺穿越。它是拖延压力，不是 Boss 出场计时器。

### 6.3 学分与绩点现状

学分在局内 HUD 显示，击败 Boss 还增加 4 学分；目前学分不是通关门槛，也没有局外消费用途。

模型中的 GPA 计算是“作业提交比例 × 2.7 + 曾击败 Boss 的加分 1.0 + 剩余生命比例 × 0.3”，限制在 0–4。它既不是每门课成绩，也不是八 Boss 完成比例；当前结算界面没有展示该值。后续若正式启用，应重新设计名称与算法，避免给玩家错误预期。

### 6.4 校园系统的候选扩展

以下尚未立项实现：

- 把通用高数作业改为所选方向的任务主题，保留统一且可读的目标。
- 给“学分”确定单局作用，例如可选择的临时增益；是否引入取舍，先做小实验。
- 独立课程考试用专业能力检验表现，不在战斗中突然插入长文本答卷。
- 绩点若加入结算，应能说明评分因素，但完整通关时间仍是竞速主目标。

每次只验证一个变量，避免选课、绩点、课表和商店同时进入核心战斗。

“可辨识”是设计意图，尚没有玩家盲认数据支持，不能直接宣称辨识率达标。

### 7.3 强度与公平性

- 普通关 Boss 生命：`2000 + 已击败Boss数×880 + 最高索引×205`；最终关生命 18000。
- 接触伤害 30；远程伤害为 `17 + min(当前轮次, 8)`；不同范围招式另设伤害。
- 半血后进入第二阶段，范围招式间隔由 4.7 秒缩到 3.3 秒，弹幕间隔由 3.8 秒缩到 2.5 秒。
- 范围招式保留不少于 1.1 秒的预警，预警位置固定后不偷偷追随玩家。
- 加强优先来自组合、节奏和可读的第二阶段，不能只反复叠加血量和屏幕占用。
- 远程弹幕本身也需可躲；近距离生成、连续攻击重叠以及小屏幕无安全通道应列为重点体验问题。

### 7.4 新 Boss 入库模板

每个提案必须填写：清北关联、来源日期及链接、事实/陈述/虚构边界、静止剪影、主色、代表物件、至少一种远程攻击、一种范围攻击、预警、空道、第二阶段变化、击杀收尾、手机可读性、验收记录。

熟悉题材的玩家应能通过“轮廓 + 物件 + 招式”识别；陌生玩家应能通过预警学会躲避。战斗图鉴已经取消，不依赖阅读图鉴补救难以辨认的战斗设计。

### 7.5 v0.5.0 代表图片

每个 Boss 在原有招式机体正面显示清晰图片：码农为用户给定表情截图；车王为学堂路照片；韦神为馒头矿泉水采访图；紫荆蛇园为紫荆园招牌；抢号王为鹅腿排队现场；泳测为清华泳池测试现场；热搜机甲为孙宇晨公开活动照片；最终 Boss 为二校门。图片使用完整适配显示，保留来源水印，机体外缘与招式提示继续承担机制辨识。不得将场景照片中的普通参与者描述为反派或把虚构招式当成新闻事实。

来源、图片尺寸和 SHA256 见 [v0.5.0 实物图片清单](research/0.5.0-实物图片清单.json)。本版本未增加新 Boss，也未改变基础伤害、进度门槛或通关条件。

## 8. 鹅腿阿姨与其他生存资源

|项目|当前规则|
|---|---|
|补给站位置|靠视野右侧，抛物起点与站点坐标一致|
|等待文本|**姨姨，腿腿，饿饿**；不显示倒计时|
|真有鹅腿投出|**鹅腿到了！**；站点独立提示约 2.8 秒，不被其他战斗公告覆盖|
|全鸭批次|不提示鹅腿到了；保留风险提示|
|飞行|曲线路径，约 8 秒后离场，末段提示即将飞走|
|鹅腿|恢复 24 生命，上限 100；5 秒射速加餐，Q 充能 +8|
|鸭腿|扣 12 生命，战斗无敌也不抵消误食代价，可致死|
|站点被动回血|没有|
|宿舍|另一处独立保护点：3 秒无敌、35 秒冷却；不是补给站|

补给压力 `p = min(1, max(活动时间/300, 最高索引/14))`。批次间隔从 17 秒缩短到 5.5 秒；p 小于 0.15 时必有鹅腿，之后鹅腿出现概率随进度降低，最低 16%。每轮至少 1 只鸭腿，p 达 0.65 后为 2 只鸭腿；有鹅腿时额外投 1 只。因此后期可能连续多轮全鸭，不提供“每 N 轮必有鹅腿”的保底。

选择困难来自路线和时机，而非故意藏起补给类别。补给应同时有颜色、轮廓和文字，不能只靠红绿区分。敌方号码票、馒头等不得采用与可吃补给相同的提示方式。

## 9. 画面、声音与界面规范

### 9.1 场景与图层

主菜单使用二校门建筑照片，战斗使用学堂路实景。战斗背景通过连续推进、过渡和随玩家位移的视差产生动感，冲刺 / Boss 阶段加速。背景不是实际无限地图，当前世界坐标为 1200×800。

视觉优先级为：**玩家与危险 → 可拾取资源 → 关键反馈 → 场景装饰**。中央徽章不得被照片、技能或横幅完全盖住。持续粒子、震动与闪白需要保持克制，保留系统减少动态效果的兼容路径。

### 9.2 爽感不是单纯变亮

|触发|应有反馈|不可损坏的体验|
|---|---|---|
|普攻命中|短促亮点、清楚的目标受击|不能永久闪成白块|
|合成|环形爆发、击退、徽章升级、音效|玩家仍能定位自身|
|Q 技能|该专业的图形 / 符号和明显战场作用|显示范围与命中一致|
|车神|照片淡入、加速拖尾、碰撞反馈|照片上方始终能看见徽章|
|Boss 登场 / 变阶段|名称、短提示、独立造型与节奏变化|不遮住立即需要躲避的区域|
|胜负|先冻结成绩、战斗收尾，再结算|不突然切断最后一次攻击反馈|

线上 v0.5.2 为程序音效。v0.6.0 候选接入贡献者 PR #1 的四首配乐：生命低于 50 使用紧急曲，其他正常战斗使用主曲；胜负曲单次播放。曲目切换 1.2 秒渐变，目标音量 0.3，与音效开关联动；暂停及切后台停播。用户首次交互后才请求音乐，最多两首流式媒体，销毁时释放。音频加载/自动播放失败不阻塞游戏，后续交互可重试。来源与未注明授权状态见配乐接入记录。同帧相同程序音效去重。

### 9.3 界面

- 开局：开始、操作说明、声音开关；选择主修时有搜索、分组选择和当前技能说明。
- 战斗：生命、时间、合成/Boss 进度、当前任务、暂停/音效、库存与三个操作按钮。小屏可简化任务信息。
- 结算：胜负、本次/完整用时、已合成时刻、Boss 数、合成次数、最高连破；可重新挑战或改主修。
- 不把技术参数、资料来源、版本管理说明塞进战斗 HUD。
- v0.4.1 仍有少量“审核机”等旧称文案，需要以后统一成“二校门 / 最终 Boss”；本版尚未统一这些残留文案。

## 10. 操作与移动端

|动作|桌面|手机横屏|
|---|---|---|
|移动|WASD / 方向键|左侧摇杆|
|普攻|自动瞄准与发射|自动|
|徽章合成|E|右侧合成|
|车神冲刺|空格|右侧车神|
|院系绝招|Q|右侧院系绝招|
|暂停 / 继续|P / Esc / 按钮|界面按钮|

v0.5.2 从首页起默认横屏。手机浏览器视口仍为竖屏时，整块游戏舞台顺时针旋转 90°；实际横屏后自动取消旋转。首次进入选系时可尝试浏览器全屏和方向锁定，但不以接口成功作为进入条件。菜单、选系、操作说明、战斗、暂停和结算都在同一舞台内；物理竖屏不再阻断战斗和计时，后台/主动暂停沿用。

Canvas 使用变换前 clientWidth/clientHeight；响应断点、字号和控件尺寸使用逻辑宽高。刘海安全区随旋转换边；摇杆将屏幕点逆旋转到局部坐标，再计算移动方向。窗口改变时刷新模式并复位输入，即使旋转前后逻辑宽高相同也刷新。按主要指针和悬停能力区分触控与桌面，桌面不旋转、不出现摇杆。

触屏左下触区宽为逻辑游戏视口 44%（上限 400 CSS 像素），高为视口 53%（上限 260）；左、底边避让安全区。摇杆休息位置贴近左拇指，按下后原点跟随手指，不突然转向；拖动 42 CSS 像素满速，12% 死区。徽章栏位于底部中央；冲刺触区 76×76，其余 66×66，位于右侧。独立触点允许同时移动与技能；松手、取消、窗口失焦、旋转和组件卸载均复位。离屏 Boss 有方向箭头。

加载请求 4.5 秒超时，最多两次尝试；每批 12 秒等待预算，超时后停止派发该批队列。v0.6.0 候选进一步让所有批次共用 3 个请求名额；同 URL 的请求合并。成功图片缓存复用，缺图时可先开始并使用文字/程序图形，菜单提供重试图片入口。新增 Canvas 圆角路径与视口高度回退；静态脚本以 ES2020 为目标。以上为实现与程序测试结论，OPPO 微信真机待验收。

下一阶段真机验收至少包含一台 iPhone Safari 与一台 Android Chrome，并记录型号、系统、浏览器版本、横屏可用区域和实际帧率。建议覆盖多指同时操作、浏览器工具栏伸缩、刘海安全区、前后台切换、横竖切换和连续重开。

v0.5.1 当前优化：附近怪物网格查询保留原命中顺序；同款子弹预绘制缓存最多 64 张 224×96 画布（约 5.5 MB 像素数据，不含浏览器额外开销）；课本映射复用；触屏/桌面装饰粒子绘制上限为 70/120，文字、光环、敌弹与危险区不受这个上限影响。Canvas 触屏 DPR 上限仍为 1.5，离屏剔除沿用。1,000 颗子弹与 65 个分散怪物的程序用例候选检查由 65,000 次降至 1,365 次，命中与追踪顺序一致；这是运算计数，不代表手机 FPS。

建议性能目标：常见设备接近 60 FPS，低档目标设备仍可在 30 FPS 下连续操作；以连续 10 分钟压力场景和典型高弹量 Boss 场景测量。当前未测得这些数据，不能据此宣传达标。

v0.6.0 候选的发布图片为 WebP 内容哈希副本：235 张约 3.17 MB；原图约 20.38 MB 继续保留在 Git，静态包不复制原图。首次等待仅 4 张约 467 KB，选系加载该学科课本；徽章与下一位 Boss 在进度到达前后台请求，失败至少间隔 20 秒重试。没有承诺离线可用或永不失效的缓存；HTTP 缓存仍由浏览器管理。12 张教材缩略图上限、30 Hz 背景缓冲与菜单/暂停降频均只调整渲染，不调整攻击、命中或计时规则。

## 11. 内容、素材与工程现状

### 11.1 内容来源与复用

### 11.3 长期维护的技术债

1. 大量战斗与绘图分支集中在两个文件中；后续按输入、战斗、技能、Boss 与表现逐步拆分，但每次必须保持既有回归。
2. 126 方向仍以三类基础 profile 承载；名称、弹道与强度需逐步脱离粗略映射。
3. `exam` 等早期字段保留了判定与绘制逻辑，但正常流程未见创建完整考试事件；清理前区分无效分支与尚待实现的功能。
4. 源码和原包已有本地 Git 与不可覆盖归档；公开 GitHub 仓库目前主要保存部署 ZIP、更新说明和工作流，不能把它当作完整远端源码备份。远端源码管理应优先补齐。
5. 没有固定种子挑战入口、回放或历史成绩；目前随机链与随机 Boss 顺序不同，跨局用时只适合自我挑战，尚不足以支撑严肃全服排行。

## 12. 长期路线图（建议，尚未作为排期承诺）

按“先稳定可玩 → 建立竞速复玩 → 扩展校园系统”的顺序推进。每阶段只承诺可验证的交付物，具体日期和版本号在开始该阶段时确定。

|阶段|要解决的问题|建议交付|退出标准|
|---|---|---|---|
|M1：稳定战斗体验|能玩但可读性、手机和强度缺真实反馈|8 Boss 识别试玩、手机真机验收、代表主修平衡、卡顿记录、源码远端备份|P0 问题关闭；代表设备能完成完整一局；不靠解释也能理解预警|

## 14. 制作流程与完成标准

### 14.1 一次更新的工作单

```text
变更编号：
目标版本（候选）：
玩家当前遇到的问题：
本次改动范围：
沿用 / 改变的既有规则：
需要的素材及来源：
可观察的验收条件：
涉及文件 / 系统：
验证方式与结果：
尚未验证的部分：
回滚目标与原包：
最终状态：待做 / 进行中 / 待验收 / 候选完成 / 已发布
```

提出新点子可以直接先登记，不需要把所有灵感同时变成迭代任务。用户决定产品取舍与体验反馈；执行者负责实现、说明假设、记录证据和发布；真人测试由实际使用设备的人留下结果。当前未设定额外固定团队成员。

### 14.2 功能完成不等于发布完成

|阶段|必须满足|
|---|---|
|设计可开工|问题、范围、影响与验收条件明确；用既有决定能解决的常规实现选择自行推进|
|开发完成|实现可复现，关键规则测试通过，旧功能未被意外删除|
|候选版完成|类型、lint、逻辑回归、静态导出、生产构建通过；资料更新；原包与源码封存|
|体验验收|按本次范围执行实际游玩或设备检查，记录已做与未做；不能用模型模拟代替真机|
|公开发布|GitHub 版本说明/标签齐全，部署成功，线上文件核验，上一版可恢复|

自动模拟是发现规则问题的工具，不是“玩家一定觉得爽”的证明。涉及移动端、画面布局或 Boss 辨识度的变更，应把真实游玩列入工作单；如果未做就保留未验证标记。

### 14.3 文档维护

- 本文是设计总入口；`CHANGELOG.md` 是每版变更记录；`docs/releases/` 是不可用口头结论替代的证据。
- 调整数值时同步对应节与配置来源；附录 A 从方向数据导出，不手工维护另一套不同命名。
- 本文有独立文档版本。纯文档修订不递增游戏版本，不重新打包或部署游戏。
- 新功能从“规划”移动到“当前实现”必须附上实际版本；废弃决定保留历史说明。
- 需要回滚时，说明同时恢复哪些规则与内容；不删除新版设计和历史讨论。

## 横屏实现依据

浏览器方向锁定兼容性有限，通常受全屏条件限制，不能当作微信入口的唯一方案：[MDN ScreenOrientation.lock](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)。因此本版使用页面内部横屏舞台兜底；浏览器自身工具栏和系统键盘不属于游戏画面，网页不控制它们的方向。

开发入口为 `npm ci` → `npm run dev`，不依赖 Codex、OpenAI 账号或本机托管配置。完整工程包括源码、锁文件、资源、回归脚本和文档。个人 `.openai` 配置、生成目录、未提交私人资料和凭据不进入公开工程。
