# 全服排行榜部署与维护

前端继续使用 GitHub Pages。排行榜是独立的 Cloudflare Pages Functions + D1，不迁移游戏托管，不把数据库凭据放前端。

## 已确定的规则

- 全服公开榜需要昵称；同一浏览器生成一个匿名参榜身份，无密码、邮箱或手机号。昵称不作为身份主键，可能重名。清除本机数据或换浏览器会失去原身份，目前不提供跨设备账号恢复。
- 每人每院系仅保留最佳成绩；院系榜查询最多 10 名。总榜每人只有一条最快成绩，查询最多 20 名。
- 只有完整通关提交成绩；服务器参数校验、身份令牌校验和数据库事务保证重复、较慢及并发提交不会覆盖更快成绩。此版本信任客户端报告用时，是休闲成绩榜，不提供服务器回放或防作弊认证。
- 服务端存储每人各院系的个人最佳及一条总榜最佳，不保存游玩流水。索引按院系/时间及总榜时间排列，查询不拉取全部玩家给浏览器排序。
- 战斗中不轮询排行榜。页面只读一次服务地址；打开榜单时读取最多 10/20 条，客户端缓存 30 秒，通关成功提交后清除榜单缓存。请求 6 秒超时，失败不影响游戏或本机成绩，当前页面可手动重试。
- 本机历史纪录仍单独保留院系 10 / 总榜 20；它不是全服榜。昵称和成绩会公开展示，令牌只保存在当前浏览器；数据库只保存令牌哈希，不在榜单返回令牌。

## 本项目生产服务

API：https://campus-overdrive-scores.pages.dev；游戏仍在 GitHub Pages。Pages Functions 使用 `server/leaderboard/worker.ts` 的同一套 API 逻辑，绑定 `campus-overdrive-scores` D1 数据库。

2026-09-08，生产 API 已通过 25 个测试玩家验收：院系10/总榜20、排序、个人最佳、并发提交、身份隔离与 CORS；测试玩家和成绩均按精确 ID 清理。[部署记录](releases/0.6.2-backend.json) · [验收记录](releases/0.6.2-api-validation.json)。前端 v0.6.2 已经 PR #4 发布，线上 245 个文件核验一致；未实测 OPPO 微信。

最初 Worker 的 workers.dev 地址在当前网络遇到 DNS/TLS 错误。Pages Functions 地址经原连接及直连 health 验证通过，复用原数据库，不需要购买域名。原 Worker 部署保留作追溯，前端只使用已验证的 Pages API 地址。

## 其他贡献者首次部署

使用自己的 Cloudflare 账号和新建数据库，不要把本项目生产数据库 ID 当作自己的资源。项目使用已有固定版本 Wrangler：

```sh
npx wrangler login
npx wrangler d1 create campus-overdrive-scores
```

把数据库 ID 分别填入 `server/leaderboard/wrangler.jsonc` 和 `server/leaderboard/pages/wrangler.jsonc`。两个配置应绑定同一个数据库。将两个 ALLOWED_ORIGINS 改为自己的游戏前端源站（仅协议与域名，不含仓库路径），并选择自己可用的 Pages 项目名。

```sh
npx wrangler d1 migrations apply DB --remote --config server/leaderboard/wrangler.jsonc
npx wrangler pages project create campus-overdrive-scores --production-branch main --compatibility-date 2026-05-22
npm run deploy:leaderboard
```

部署脚本先通过 Wrangler 构建 API，在系统临时目录组合 Pages 包，再上传到配置中的项目，最后清理临时目录。临时目录用于避免主游戏 Vite 生成的 `.wrangler/deploy/config.json` 干扰 API 部署。API 逻辑不复制、不分叉；`_routes.json` 只将 `/api/*` 交给服务端。

取得实际 HTTPS 服务地址后，验证 health、CORS、昵称登记、成绩提交、院系和总榜排序。验收数据应只按确切测试玩家 ID 清理。通过后填入 `public/leaderboard.json` 的 apiBase，再运行游戏检查、构建、封存及 GitHub PR/CI/Pages 发布核验。不要把示例域名当成已部署地址，也不要把上传成功当成手机访问已经通过。

## 本地验证

```sh
npm run test:leaderboard
```

该测试创建临时本地 D1，启动真实 Worker，使用 25 个测试玩家验证 API、10/20 上限、同一玩家跨院系总榜去重、并发仅保留最快成绩、身份隔离、CORS 与无效提交，完成后停止进程并删除测试数据库。不会访问远端数据库。

开发服务可以单独启动：

```sh
npx wrangler d1 migrations apply DB --local --config server/leaderboard/wrangler.jsonc --persist-to outputs/leaderboard-dev
npx wrangler dev --local --config server/leaderboard/wrangler.jsonc --persist-to outputs/leaderboard-dev --port 8787 --var ALLOWED_ORIGINS:http://127.0.0.1:3000
```

本地联调可暂时将 apiBase 设为 http://127.0.0.1:8787；公开包必须恢复为真实 HTTPS 服务地址。

## 回滚与保留数据

- 游戏原包回滚到 v0.6.0 不修改 D1，用户成绩保留。
- 排行榜 schema 1 保持向后兼容，不在普通发版时清空数据库或删除玩家。
- 需要后端回滚时优先使用 Cloudflare Pages 历史部署（原 Worker 可查看对应 Worker 历史）；数据库迁移采用新增迁移，不能靠覆盖旧文件重写已执行迁移。
- 当前后端支持 semver 游戏版本记录；若以后改动影响成绩可比性，应另建计分赛季/规则集，不能将不同规则成绩直接混排。

Pages API 部署依据：[Advanced mode](https://developers.cloudflare.com/pages/functions/advanced-mode/)、[D1 bindings](https://developers.cloudflare.com/pages/functions/bindings/)。
